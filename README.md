# tg-assistance-bot

Telegram-бот на [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI) и [Telethon](https://docs.telethon.dev/): принимает картинку в чате и по подтверждению публикует её в сторис подключённого аккаунта.

Несколько человек могут пользоваться ботом одновременно. У каждого своя сессия в PostgreSQL; пользователь авторизуется только в переписке с ботом.

## Как это работает

1. Пользователь пишет `/start` и один раз подключает свой Telegram: номер телефона → код из Telegram → облачный пароль, если включена 2FA.
2. Бот сохраняет сессию этого `telegram_id` и сам обновляет её после логина и каждой публикации.
3. Пользователь присылает картинку. Бот спрашивает «Опубликовать в сторис Telegram?» с кнопками **Да** / **Нет**.
4. **Да** — сторис уходит в аккаунт этого пользователя. **Нет** — диалог сбрасывается, можно прислать новое фото.

Пока сессия жива, телефон и код больше не нужны. Повторный вход — `/login`, если Telegram сбросил сессию, или `/logout`, чтобы выйти самому.

## Команды

| Команда | Описание |
|---------|----------|
| `/start` | приветствие; если аккаунт не подключён — запрос номера |
| `/login` | подключить аккаунт заново |
| `/status` | подключен ли аккаунт (без секретов) |
| `/logout` | удалить сессию |

Бот отвечает только в личных чатах.

## Переменные окружения

Задаёт тот, кто деплоит сервис, в `.env` на хосте. Пользователи бота их не вводят.

| Переменная | Назначение |
|------------|------------|
| `BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `API_ID`, `API_HASH` | ключи приложения Telethon с [my.telegram.org](https://my.telegram.org) |
| `PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGPORT` | PostgreSQL (`PGPORT` по умолчанию 5432) |

Файл `.env` подхватывается через `python-dotenv`.

## Установка и запуск

Нужен Python 3.9+.

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

При старте проверяется подключение к БД и создаются таблицы `users` и `pending_stories`. Процесс должен работать постоянно (long polling).

## Структура репозитория

- `main.py` — точка входа, polling.
- `controller/` — команды, логин в чате, фото, кнопки Да/Нет.
- `model/` — PostgreSQL и Telethon (логин и публикация сторис на сессию пользователя).
- `view/` — тексты и клавиатуры.

Версия приложения задаётся в `version.py`.
